**基準は「LINE アプリの中でしか起こらないこと」。** デスクトップの Chrome では原理的に到達できない項目だけを集めている。

- **所要**: 5〜10分

- **やる人**: 人間（スマホ実機）。Claude は実行できない

Chrome で確認できる範囲（見た目・API 通信・MPA と LIFF の一貫性・コンソールエラー）は [`.claude/skills/regression-test/SKILL.md`](../.claude/skills/regression-test/SKILL.md) が担当する。**重複して確認しない。**

## この確認でしか分からないこと

| 分類 | 例 | なぜ実機だけか |

| LINE アプリの機能 | QR・リッチメニュー・共有シート | アプリの外からは呼べない |

## 最後に: 本番 DB を確認する（必須）

**画面に出ている＝DB に入っている、ではない。** 特に項目14（上書き修正）は、`round_number` が送られていないと**上書きではなく局が増える**。画面には修正後の値が正しく出るため、目視では絶対に気づけない。

全項目を終えたら、EC2 へ SSH して実機で作ったレコードを確認する。

```bash
ssh -i ~/.ssh/mahjong-score-key.pem -o StrictHostKeyChecking=no ec2-user@3.114.238.160
```

```bash
cd /home/ec2-user/mahjong_score && docker-compose exec -T web bin/rails runner 'g = Game.order(:created_at).last; puts({id: g.id, players: g.players.order(:created_at).pluck(:name), rounds: g.rounds.count, numbers: g.rounds.order(:round_number).pluck(:round_number), sums: g.rounds.map { |r| r.scores.sum(:point) }, counts: g.rounds.map { |r| r.scores.count }}.to_json)'
```

| 見るもの | 合格 |
|---|---|
| `players` | 実機で入力した4名と同じ・**同じ順序** |
| `rounds` | 入力した局数と一致。**項目14の修正で増えていないこと** |
| `numbers` | 重複なし |
| `sums` | 全部 `100000` |
| `counts` | 全部 `4` |

> **`exec` を使う（`run --rm` ではない）。** EC2 は gem を Docker ボリュームに永続化していないため、使い捨てコンテナには gem が無く `Bundler::GemNotFound` で失敗する。本番は `docker-compose`（ハイフン付き）。

## 12局データの作り方（項目6の準備）

本番に12局埋まったゲームが無ければ、上の SSH 先で作る。

```bash
cd /home/ec2-user/mahjong_score && docker-compose exec -T web bin/rails runner '
rule = { mochi_ten: 25000, kaeshi_ten: 30000, rank_1_bonus: 50, rank_2_bonus: 10, rank_3_bonus: -10, rank_4_bonus: -30 }
g = Game.create_with_players!(rule, %w[東 南 西 北])
ps = g.players.order(:created_at).to_a
(1..12).each do |n|
  r = g.rounds.create!(round_number: n)
  [40000, 30000, 20000, 10000].each_with_index { |pt, i| r.scores.create!(player: ps[i], point: pt) }
end
puts "GAME_ID=#{g.id}"
'
```

合計は `720.0 / 120.0 / -240.0 / -600.0` になる。URL は `https://dxop25dcw25sl.cloudfront.net/games/<GAME_ID>`。
